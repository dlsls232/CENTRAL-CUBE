# Этап 8 — подготовка сборки и консистентность версии

## Выполнено
- Исправлено расхождение версии Python-пакета: `central_cube.__version__` обновлён с устаревшей `0.1.4` до фактической версии проекта `1.0.0`.
- README приведён к версии `1.0.0`.
- Windows Agent больше не хранит номер версии в нескольких строковых литералах: CLI `--version` и стартовое сообщение используют `central_cube.__version__`.
- Страница «О программе» GUI использует единый номер версии пакета.
- Добавлены регрессионные тесты, проверяющие совпадение версии в Python-пакете, `pyproject.toml`, Inno Setup metadata и README.
- Добавлен `PROJECT_PROGRESS_RU.md` для безопасного продолжения работы между сеансами.

## Проверки
- `python -W error::ResourceWarning -m pytest -q`: **53 passed**.
- `python -m compileall -q src tests`: успешно.
- `PYTHONPATH=src python -m central_cube.agent.main --version`: успешно, вывод `CentralCubeAgent 1.0.0`.
- Поиск устаревшего `0.1.4` в README, исходниках, installer и pyproject: совпадений не найдено.

## Непроверенные возможности
- PyInstaller и Inno Setup фактически не запускались: текущая среда не является Windows build runner.
- GitHub Actions workflow не выполнялся в реальном GitHub Actions runner.
- PySide6 GUI runtime не запускался, так как PySide6 отсутствует в текущем окружении.
- Установка, обновление и удаление через Windows installer не проверялись.

## Следующие шаги
Версия `1.0.0` пока **не присваивается**, потому что обязательные Windows QA и build/install проверки не подтверждены фактически. Следующий этап должен выполнить эти проверки на Windows и обновить конфигурацию сборки только по результатам реальных прогонов.
