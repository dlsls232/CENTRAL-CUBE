# Архитектура CENTRAL CUBE 1.0.0

CENTRAL CUBE сохраняет архитектуру исходного проекта: настольный контроллер на PySide6, локальное хранение данных в SQLite и отдельный Windows Agent для ограниченного набора удалённых операций.

## Основные компоненты

- `central_cube.ui` — пользовательский интерфейс, управление устройствами, отчёты и фоновые сетевые задачи.
- `central_cube.core` — SQLite, pairing, настройки, резервное копирование и экспорт.
- `central_cube.network` — ограниченный JSON-протокол, TLS/mTLS-клиент и Wake-on-LAN.
- `central_cube.agent` — TLS-сервер агента, allowlist доверенных клиентских сертификатов, rate limiting, anti-replay и allowlist команд.

## Поток управления

1. Пользователь выбирает зарегистрированное устройство в GUI.
2. Сетевые операции выполняются вне GUI-потока.
3. Контроллер устанавливает TLS-соединение и проверяет сертификат агента.
4. Агент требует доверенный клиентский сертификат, проверяет fingerprint и входящее сообщение.
5. Выполняется только команда из allowlist; опасные power-команды дополнительно выключены по умолчанию.
6. Использованный `command_id` сохраняется в SQLite anti-replay store.
7. Результат и значимые действия фиксируются в журналах.

## Хранение данных

SQLite используется для устройств, настроек, журнала и anti-replay данных. Миграции выполняются без штатного удаления пользовательских таблиц. Для обслуживания доступны проверка целостности и резервное копирование через SQLite Online Backup API.

## Ограничения

Архитектура не включает произвольное удалённое выполнение команд, автоматический выпуск сертификатов или облачный relay. Windows Service не реализован: штатный автозапуск агента выполняется через Scheduled Task при входе пользователя.
