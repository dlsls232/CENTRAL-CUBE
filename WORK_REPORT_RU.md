# CENTRAL CUBE 0.1.4 — отчёт о доработке

## Изменения этого этапа
- Добавлен mTLS контроллерский клиент: проверка CA цепочки, обязательный клиентский сертификат, проверка SHA-256 fingerprint агента.
- Добавлены сетевые команды `ping` и `system_info` через реальный защищённый канал.
- Агент требует TLS context с `CERT_REQUIRED`; отклоняет неизвестные команды, некорректный `confirmed` и повторные command ID в рамках процесса.
- Реальные `shutdown`, `restart`, `sleep` доступны только при запуске агента с `--enable-power-actions` и явном подтверждении в запросе; по умолчанию выключены.
- Добавлен JSONL журнал событий агента.
- Реализовано одноразовое сетевое mTLS-сопряжение: код 6 цифр, TTL 300 секунд, блокировка после 5 неудачных попыток, сохранение fingerprint клиента в allowlist. Выпуск сертификата по-прежнему выполняется внешней PKI.
- Добавлен обязательный fingerprint allowlist клиентских сертификатов на агенте; точечный отзыв выполняется удалением fingerprint и перезапуском.
- Bulk Actions дополнен реальным mTLS Ping по всем устройствам с журналированием каждого результата.
- GUI получил пункт «Удалённая команда» с выбором команды, подтверждением опасных действий, выбором CA/client certificate/private key, результатом и SQLite аудитом.
- Проверка TCP теперь обновляет `last_seen`.
- Реализован автозапуск приложения через Windows HKCU Run; добавлены PowerShell-скрипты установки/удаления задачи автозапуска агента при входе пользователя. Это не Windows Service. Добавлены скрипты установки/удаления inbound firewall rule, ограниченного TCP портом, LocalSubnet и профилями Domain/Private.
- Реализован LAN-only Wake-on-LAN: хранение MAC в SQLite, Magic Packet UDP broadcast на порт 9 и журналирование отправки. Добавлена миграция старой схемы БД.
- Обновлены версии, сборочные скрипты и инструкции mTLS PKI.

## Проверки
- pytest: 38 тестов (все успешно).
- Добавлен интеграционный тест локального mTLS соединения с тестовой CA, server cert, client cert и фактическим запросом `system_info` к запущенному asyncio агенту.
- Windows GUI и EXE по-прежнему не запускались в этой Linux-среде; PyInstaller/Inno Setup не подтверждены.

## Известные блокеры production 1.0
- Одноразовое сетевое сопряжение реализовано: агент выдаёт шестизначный код на 5 минут, принимает его один раз и сохраняет fingerprint клиентского сертификата в allowlist. Сам клиентский сертификат по-прежнему выпускается вручную внешней PKI.
- Нет CRL/OCSP; точечный отзыв через allowlist доступен, но требует перезапуска агента.
- Anti-replay cache агента находится в памяти процесса и сбрасывается при рестарте.
- Нет Windows Service installer и системного трея; агент запускается по расписанию при входе пользователя.
- Нет фонового выполнения GUI сетевых задач; запрос может временно блокировать интерфейс до тайм-аута.
- Покрытие всего приложения не превышает 80%: UI и entrypoints не входят в 88% выбранного функционального ядра. Windows QA и Inno Setup build не выполнялись.

## Сборка
На Windows 10/11 с Python 3.11+: `scripts\\build_windows.bat`. Затем Inno Setup 6: открыть `installer\\CentralCube.iss` и собрать установщик. Перед распространением провести Windows Defender/SmartScreen проверку, подпись кода Authenticode и аудит PKI.

## Этап 2 — устранение повторного принятия старых command_id

- Удалено автоматическое удаление старых записей из `used_commands`.
- Зафиксировано постоянное хранение ID в SQLite replay store агента.
- Добавлен регрессионный тест: исторические ID остаются в БД и отклоняются после создания нового экземпляра сервера.
- Проверка после изменения: `pytest -q` — 42 passed (0.89 s).

Ограничение: это исправляет очистку replay-таблицы, но не решает остальные риски из `docs/AUDIT_STAGE_1_RU.md` (rate limiting, отзыв/ротация сертификатов, GUI worker threads, DPAPI и Windows CI smoke tests).


## Этап 3 — ограничение сетевой нагрузки и исправление SQLite resource leak

- Добавлен token-bucket rate limiter на источник: burst до 20 запросов, затем пополнение 1 токен/секунду. Ограничитель применяется до чтения протокольного сообщения.
- Таблица источников ограничена 4096 записями; при churn адресов вытесняется самая давно обновлявшаяся запись.
- Добавлены TLS handshake timeout 10 секунд и TLS shutdown timeout 5 секунд.
- Исправлено закрытие SQLite connections в replay store: контекстный менеджер sqlite3 сам по себе не закрывает соединение, теперь соединения гарантированно закрываются.
- Добавлены тесты burst/refill, независимости IP и ограничения памяти rate limiter.
- Проверки в Linux/Python 3.13: `pytest -q` — 44 passed; `compileall` — успешно; выборочное покрытие server/database/protocol — 88%.
- При запуске coverage до исправления были замечены ResourceWarning о незакрытых SQLite connections; после исправления повторный прогон требуется подтвердить отдельно.

Ограничения: rate limiting по IP не заменяет firewall/connection caps и не защищает TLS handshake до вызова обработчика; TLS handshake timeout сокращает окно удержания ресурсов. Полноценная Windows-сборка не выполнялась.


## Этап 4 — отзыв клиентского сертификата без перезапуска агента

- Добавлен метод `AgentServer.revoke_client(fingerprint)`: нормализация и строгая проверка SHA-256 fingerprint, удаление из allowlist и атомарная запись нового allowlist через временный файл и replace.
- При ошибке записи fingerprint возвращается в оперативный allowlist; отзыв не считается успешным.
- Событие отзыва фиксируется в audit JSONL. Новые TLS-сессии с отозванным сертификатом будут отклонены; уже установленные сессии автоматически не разрываются.
- Добавлены тесты формата fingerprint, постоянного хранения отзыва и восстановления состояния после создания нового сервера.
- Проверка после этапа 4: `python -W error::ResourceWarning -m pytest -q` — 46 passed; `python -m compileall -q src tests` — успешно.
- Ограничение: функция отзыва добавлена на уровне API агента, но отдельный административный CLI/GUI workflow для вызова отзыва ещё не реализован.

## Этап 6 — фоновые операции GUI

Добавлен QRunnable/QThreadPool механизм. Индивидуальная и массовая TCP-проверки перенесены из GUI-потока в worker; обработка результатов, запись аудита и обновление виджетов выполняются через Qt-сигналы в GUI-потоке. Ошибки worker показываются пользователю. При закрытии окна выполняется ожидание активных задач.

Проверки: compileall PASS; pytest 50 passed. Ruff не установлен; PySide6 отсутствует, поэтому GUI runtime-тесты не запускались. mTLS pairing/remote commands и bulk remote ping пока синхронны. См. docs/WORK_REPORT_STAGE_6_RU.md.
